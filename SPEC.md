# Спецификация local_code_worker

## 1. Назначение
Локальный ИИ-агент для работы с кодом через веб-интерфейс, работающий с локальными папками проектов на диске. Агент самостоятельно ищет код, читает фрагменты, вносит точечные правки, запускает тесты и команды, отчитываясь о каждом ходе. Рассчитан на одного пользователя, использует модель **gpt-oss-20b** через AI Manager.

## 2. Архитектура: модули lcw/*

| Модуль | Путь | Назначение |
|---|---|---|
| `server.py` | `lcw/server.py` | FastAPI: REST + SSE для веб-интерфейса, маршруты API, авторизация. |
| `agent.py` | `lcw/agent.py` | Агентный цикл, подтверждения, автопроверка, сжатие контекста, откат ходов. |
| `sessions.py` | `lcw/sessions.py` | Управление сессиями: история (messages), элементы для UI (items), поток операций (SSE). |
| `llm.py` | `lcw/llm.py` | Асинхронный клиент AI Manager: стриминг chat/completions, управление моделью, обработка ошибок. |
| `tools.py` | `lcw/tools.py` | Инструменты агента (symbols, read, edit, test и др.), их описания и реализация. |
| `worktree.py` | `lcw/worktree.py` | Изолированная работа сессии в git worktree: создание, применение патчей, удаление. |
| `config.py` | `lcw/config.py` | Настройки из `.env`, пути к данным, параметры модели и агента. |

## 4. Сессия

**Модель данных:**
*   `id`, `project_id`, `title`, `created`, `updated`.
*   `system`: системный промпт (фиксируется при создании).
*   `messages`: история для модели.
*   `items`: элементы для UI (сообщения, статусы инструментов).
*   `checkpoints`: контрольные точки для отката (`{turn, files}`).
*   `turn`, `rewind_floor`: текущий ход и минимальный ход для отката.
*   `settings`: режим (`ask`/`edits`/`auto`), глубина рассуждений (`low`/`medium`/`high`).
*   `plan`: текущий план агента (`[{text, status}]`).
*   `worktree`: данные изолированной копии (если есть).

**Элементы (items) и статусы:**
*   Элементы добавляются через `add`, обновляются через `set`, дописываются через `append` (стриминг).
*   Статусы плана: `todo`, `doing`, `done`, `failed`.

**Хранение и прерывание:**
*   Сессии сохраняются на диск в `data/sessions/<id>.json`.
*   Остановка (`/stop`) или ошибка посреди хода: ожидающие подтверждения отменяются, пункты в статусах `running`/`approve` получают статус `denied` с выводом «прервано», незакрытый вызов инструмента дополняется ответом «Прервано пользователем» (иначе история модели становится некорректной), сессия сохраняется.
*   Пока в плане есть незакрытые шаги, агент не завершает ход сам — получает напоминание (до 2 раз).
*   Откат (`rewind`) возвращает файлы к состоянию до указанного хода и обрезает историю.

## 5. Инструменты агента

| Инструмент | Назначение | Ограничения/Подтверждение |
|---|---|---|
| `plan` | Задать план мелких шагов. | Обязателен перед изменениями. |
| `decide` | Зафиксировать решение по пункту запроса. | Требуется до правки пункта. |
| `symbols` | Индекс сущностей (классы/функции). | Поиск по именам и докстрингам. |
| `read` | Читать файл или сущность (`symbol`). | Обрезка длинных строк, лимит строк. |
| `glob` | Поиск файлов по шаблону. | |
| `grep` | Поиск текста в файлах (regex). | Лимит совпадений. |
| `refs` | Все упоминания имени (определение, импорты, использование). | Ищет целые слова, включая UPPER_CASE для настроек. |
| `test` | Запуск pytest проекта. | Краткий отчет о падениях. |
| `logstats` | Сводка лога (время, топ значений, пики). | Не читает файл целиком. |
| `edit` | Точечная замена фрагмента в файле. | Требует точного совпадения `old`. |
| `write` | Создание или полная перезапись файла. | Для новых файлов или документов (.docx). |
| `run` | Выполнение команд оболочки. | Таймаут, лимит вывода, изоляция PATH. |
| `git_commit` | add → commit → push. | **Всегда требует подтверждения**, проверка секретов и тестов. |

## 6. Работа с LLM

*   **Подключение:** AI Manager по URL из `AIM_URL`, модель `LCW_MODEL`.
*   **Повторы:** При ошибках формата (LLMError с флагом `transient`) или сетевых сбоях агент повторяет шаг до `LCW_RECOVER_TRIES` раз после ожидания `LCW_BUSY_WAIT`.
*   **Лимиты:** Контекст модели `LCW_CONTEXT` (по умолчанию 100000), лимит ответа `LCW_MAX_TOKENS` (8192).
*   **Оптимизация:** Кэш KV префикса, сжатие истории при 75% контекста (`LCW_COMPACT_AT`), отправка только рассуждений текущего хода.

## 7. Изоляция изменений

*   **Worktree:** Сессия может работать в изолированном `git worktree` на ветке `lcw/<id>`.
*   **Применение:** Изменения переносятся в рабочую копию через `apply` (патч без коммита).
*   **Что не переносится:** Неотслеживаемые файлы `.env` (копируются для работы, но не попадают в патч), логи и данные из `.gitignore`.
*   **Удаление:** Удаление сессии удаляет worktree и ветку.

## 8. Конфигурация (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LCW_HOST` / `LCW_PORT` | Адрес и порт веб-интерфейса. | `127.0.0.1` / `9009` |
| `LCW_PASSWORD` | Пароль веб-интерфейса. | — (пусто) |
| `AIM_URL` / `AIM_PASSWORD` | URL и пароль AI Manager. | `http://127.0.0.1:8000` / — |
| `LCW_MODEL` | Имя модели в реестре AI Manager. | `gpt-oss-20b` |
| `LCW_CONTEXT` | Размер контекста модели. | `100000` |
| `LCW_AIM_PROJECT` | Имя проекта в очереди задач AI Manager. | `local_code_worker` |
| `LCW_REASONING` | Глубина рассуждений по умолчанию. | `low` |
| `LCW_MAX_STEPS` / `LCW_COMMAND_TIMEOUT` | Лимит шагов агента и таймаут команд. | `120` / `180` |
| `LCW_COMPACT_AT` | Порог авто-сжатия истории (доля контекста). | `0.75` |
| `LCW_TEMPERATURE` / `LCW_TOP_P` | Параметры сэмплирования. | `0.4` / `0.95` |
| `LCW_BUSY_WAIT` / `LCW_BUSY_POLL` | Сколько ждать занятый GPU и как часто проверять (сек). | `1800` / `10` |
| `LCW_RECOVER_TRIES` | Повторов одного шага после восстановления. | `5` |
| `LCW_MAX_TOKENS` | Лимит одного ответа модели. | `8192` |
| `LCW_TOOL_OUTPUT_CHARS` | Обрезка вывода инструментов для модели. | `12000` |
| `LCW_DATA_DIR` | Каталог данных (сессии, проекты). | `data` |

## 9. Запуск и контроль

`scripts\run.bat` — цикл с перезапуском через 5 с; автозапуск — `local_code_worker.bat` в папке «Автозагрузка» (`scripts\install_autostart.bat`, задержка 60 с). Монитор `D:\projects\services_monitor` раз в 5 мин проверяет цикл и `http://127.0.0.1:9009/`; пропавший цикл запускает заново, зависший процесс (HTTP не отвечает два прохода подряд) останавливает — цикл поднимает его.
