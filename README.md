# local_code_worker

Локальный ИИ-агент для работы с кодом через веб-интерфейс — по мотивам Claude Code.
Модель — **gpt-oss-20b** через [AI Manager](../AI_Manager) (OpenAI-совместимый `/v1`).
Рассчитан на одного пользователя.

Агент работает **прямо с папками проектов на диске**: сам ищет нужный код, читает
фрагменты файлов, вносит точечные правки, запускает тесты/команды и отчитывается.
Каждую правку видно как дифф, любой ход можно откатить.

## Запуск

```bat
scripts\setup.bat   :: venv + зависимости + .env (пароль AI Manager подставит сам, если найдёт ..\AI_Manager\.env)
scripts\run.bat     :: запуск с авто-перезапуском при падении
scripts\install_autostart.bat  :: автозапуск при входе в Windows (через 60 с, свёрнутым окном; без прав администратора)
scripts\remove_autostart.bat   :: убрать автозапуск
```

Открыть http://127.0.0.1:9009. AI Manager должен быть запущен; модель стартует
автоматически при первом запросе (или кнопкой-индикатором в шапке).

Вручную: `pip install -r requirements.txt`, скопировать `.env.example` → `.env`, `python app.py`.

## Возможности

| | |
|---|---|
| Проекты | Любая локальная папка или `git clone` по URL (с веткой). Дерево файлов, просмотр, экспорт в ZIP |
| Агент | Инструменты `symbols` (индекс сущностей), `read` (в т.ч. одной функции/класса), `glob`, `grep`, `edit` (точечная замена), `write`, `run` (команды в Git Bash / PowerShell) |
| Стриминг | Рассуждения, текст и вызовы инструментов появляются по мере генерации; перезагрузка страницы ничего не теряет |
| Подтверждения | «Спрашивать всё» / «Правки — авто, команды — спрашивать» / «Полный автомат». Безопасные команды (`git status`, `ls`…) не спрашиваются |
| Откат | Кнопка «↶ Откатить» у любого своего сообщения: файлы возвращаются к состоянию до него, история обрезается |
| Git | Инструмент `git_commit`: add → commit → (push). **Всегда** с подтверждением, в любом режиме и без «Всегда разрешать». Карточка: сообщение, описание изменений по файлам, проведённые тесты, файлы и статистика, куда push (с предупреждением для main/master). Без описания и тестов не принимается; секреты (`.env`, ключи) не коммитятся; `git add/commit/push` через `run` запрещены; push только без `--force` |
| Изменения | Панель «Изменения»: итоговый дифф всех файлов, изменённых в сессии |
| Сессии | Сохраняются на диск (`data/sessions`), можно вернуться к любой |
| `@файл` | Приложить файл к сообщению (автодополнение по `@`) |
| `/init` | Агент изучит проект и создаст `AGENTS.md` — он подхватывается в системный промпт новых сессий |
| `/compact` | Сжать историю в сводку; `/clear` — новая сессия; `Esc` — остановить агента |
| Рассуждения | Быстро / средне / глубоко (`reasoning_effort` gpt-oss), переключается на лету |

## Как обеспечена скорость

Узкое место локальной модели — обработка промпта (prefill). Поэтому:

1. **Стабильный префикс → кэш KV.** Системный промпт и описания инструментов фиксируются
   при создании сессии, история только дописывается. llama.cpp переиспользует кэш и
   считает лишь новые токены (в типичном шаге из ~6000 токенов промпта из кэша берутся ~5900).
2. **Рассуждения прошлых ходов не отправляются** (шаблон gpt-oss их и так отбрасывает) —
   только текущего хода, где они нужны для цепочки вызовов инструментов.
3. **Навигация по сущностям.** В системный промпт входит карта модулей (докстринг модуля +
   верхнеуровневые классы/функции; индекс строится через `ast` для Python и регулярками для JS/TS,
   кэш по mtime). Инструмент `symbols` ищет по именам и докстрингам и выдаёт оглавление файла с
   диапазонами строк, `read(path, symbol="Class.method")` читает ровно одну сущность — модель не
   тратит контекст на чтение файлов целиком.
4. **Компактные инструменты.** Чтение диапазонами, обрезка длинных строк и выводов,
   повторное чтение неизменённого файла возвращает короткую заглушку, правки — заменой
   фрагмента, а не переписыванием файла. Описания инструментов — короткие, на английском
   (в токенизаторе вдвое компактнее русского). Подробные диффы уходят только в UI.
5. **Сжатие истории заранее** (при 75% контекста) с сохранением префикса — сводку модель
   пишет почти без пересчёта промпта.
6. **Отмена = освобождение GPU.** «Стоп» закрывает стрим, AI Manager обрывает соединение
   с llama-server, генерация прекращается сразу.

## Работа мелкими шагами (план)

Модель небольшая, поэтому агент всегда работает по плану:

1. **Сначала план.** Инструмент `plan` задаёт список мелких шагов (одно изменение в одном
   месте на шаг), последний шаг — общая проверка. В интерфейсе план виден чек-листом и
   обновляется на месте.
2. **По одному шагу:** найти место → прочитать нужные строки → небольшая правка →
   проверить этот шаг → отметить `done` (или `failed` с причиной).
3. **В конце — комплексная проверка** (тесты, импорт, запуск).

Harness следит за выполнением:
- правки и команды без корректного плана отклоняются всегда (без плана модель сводит большую
  задачу к заглушке); до плана разрешены исследование (`symbols`, `read`, `grep`, `glob`) и
  проверки (`pytest`, `py_compile`); чтение файлов через `run` (`cat`, `sed -n`…) перенаправляется на `read`;
- незакрытый план прошлого хода остаётся в силе после «продолжай»;
- новый план из одного шага не принимается; один шаг с текстом существующего — обновление его статуса;
- ответ-отказ («слишком сложно, дайте спецификацию») без единого вызова инструмента — модель
  один раз возвращают к работе по частям;
- если модель сделала 2 изменения подряд, не обновив план, к результату добавляется напоминание;
- закончить ход с незакрытыми шагами нельзя (до 2 напоминаний);
- при сжатии контекста план переносится в сводку дословно — модель продолжает с нужного шага.

## Как обеспечена стабильность

- Точная замена в `edit` с допуском на пробелы в конце строк и CRLF; при неудаче — номера
  строк всех вхождений или самый похожий фрагмент. После правки модель видит изменённые
  строки и предупреждение о синтаксической ошибке (`.py`, `.json`).
- **Автопроверка перед завершением хода** (по всем файлам, изменённым в сессии) — агент не
  может закончить, пока не исправит:
  - синтаксис `.py`/`.json`;
  - импорт изменённых модулей интерпретатором проекта (ловит битые импорты, которые не видят
    тесты, если модуль никто не загружает); у точек входа (`main.py` и т.п.) — статическая
    проверка, что модули и имена из импортов существуют;
  - классы, ставшие абстрактными (унаследовали `abstractmethod` и не реализовали — `X()` упадёт);
  - новые модули/пакеты, которые не импортирует ни один рабочий модуль, и добавленные, но не
    используемые импорты — признаки «заглушки» и «интеграции для галочки»;
  - если в запросе есть нумерованные пункты — сверка: по каждому «сделано (где) / не сделано».
- Python проекта: найденный venv (в проекте или в родительской папке) первым в `PATH` для `run`.
- Модель занята/переключается/упала (503 очереди, обрыв, 5xx): агент ждёт освобождения GPU
  (до `LCW_BUSY_WAIT` секунд) и повторяет тот же шаг (до `LCW_RECOVER_TRIES` раз), а не обрывает ход.
- Защита от зацикливания (повтор того же вызова), лимит шагов, таймауты команд с
  убийством дерева процессов, повтор запроса к модели при обрыве до первого токена,
  авто-перезапуск упавшей модели в AI Manager.
- Пути инструментов ограничены папкой проекта.

## Настройки (.env)

| Переменная | По умолчанию | |
|---|---|---|
| `LCW_HOST` / `LCW_PORT` | `127.0.0.1` / `9009` | Для доступа из сети — `0.0.0.0` **и** `LCW_PASSWORD` |
| `LCW_PASSWORD` | — | Пароль веб-интерфейса (агент выполняет команды на машине!) |
| `AIM_URL` / `AIM_PASSWORD` | `http://127.0.0.1:8000` | AI Manager |
| `LCW_MODEL` | `gpt-oss-20b` | Имя модели в реестре AI Manager |
| `LCW_CONTEXT` | `100000` | Должен совпадать с `context` модели в реестре |
| `LCW_AIM_PROJECT` | `local_code_worker` | Имя проекта в очереди задач AI Manager (заголовок `X-Project`) |
| `LCW_REASONING` | `low` | Глубина рассуждений по умолчанию |
| `LCW_MAX_STEPS` / `LCW_COMMAND_TIMEOUT` | `120` / `180` | Лимиты агента |
| `LCW_COMPACT_AT` | `0.75` | Порог авто-сжатия истории |

## Структура

```
app.py              точка входа (uvicorn)
lcw/
  server.py         FastAPI: REST + SSE
  agent.py          агентный цикл, подтверждения, автопроверка, сжатие, откат
  tools.py          инструменты агента
  entities.py       индекс сущностей (классы/функции, докстринги, диапазоны строк)
  llm.py            стриминг-клиент AI Manager (tool calls, retry)
  sessions.py       сессии и поток операций для UI
  workspace.py      проекты, индекс файлов (git ls-files), ZIP
  prompts.py        системный промпт
static/             веб-интерфейс (без сборки)
tests/              pytest: инструменты, агент с мок-моделью, API
```
